# FACEIT CS2 Telegram bot

Репозиторий текущего кода `road_to_3_elo_bot`: локальный резерв, адаптер Telegram Serverless и работающая копия Sites/Cloudflare Workers.

## Структура

- `faceit-telegram-bot/` — локальный Node.js runner, операторская CLI, переносимое ядро, Telegram Serverless и подробная документация.
- `faceit-telegram-bot-sites/` — текущая облачная реализация: webhook, D1, PNG FACEIT Dark и постоянный кеш отчётов/Telegram file_id.

Папки намеренно оставлены соседями: CLI переключения использует такой layout. Это снимок актуальных реализаций; переносимое ядро пока дублируется и проверяется на синхронность. Новый GitHub-репозиторий не заменяет автоматически исходный репозиторий публикаций Sites.

## Возможности

- `/last [ник]` — последний завершённый матч CS2, картинка FACEIT Dark.
- `/stats [ник]` — последние до 30 матчей, картинка FACEIT Dark.
- `/setfaceit ник` — личный FACEIT в текущем чате; `/setfaceit` — показать, `/unsetfaceit` — удалить. Без аргумента `/last` и `/stats` используют эту привязку, явный ник её не меняет.
- `/setts адрес пароль` и `/ts` — зашифрованные настройки TeamSpeak только своей группы; стандартный суффикс адреса не отображается. `/setts --no-password адрес` явно сохраняет сервер без пароля. Ускоренный путь `/ts` выполняет три обращения к БД до ответа; очистка технических записей выполняется после отправки, без кеширования реквизитов.
- `/poll` — неанонимный опрос с множественным выбором и 12 вариантами: «да, в 14»–«да, в 23», «да, позже», «нет». Один опрос с общими голосами пересылается в фиксированном периоде 09:00–03:00 МСК следующего дня; с 03:00 до 09:00 действует отдельный период. На точных границах 03:00 и 09:00 первый вызов создаёт новый опрос; автоматической отправки по расписанию нет. Актуальный опрос закрепляется, снимается только известный предыдущий закреп бота.
- `/menu`, `/setup` и inline-кнопки. Ответы и карточки привязаны к исходной команде; Telegram не поддерживает reply для пересылаемого опроса.
- Прозрачные значки FACEIT 1–10 в обеих карточках, локальные оригиналы и подготовленный атлас без runtime-загрузок.
- Кооперативная остановка локального runner: завершение текущей команды и сохранение offset перед закрытием БД; без принудительного kill. Для старых процессов сохраняется безопасный drain перед переключением режима.
- Работа в любой группе или супергруппе после добавления бота и выдачи необходимых прав; список разрешённых chat ID не используется. В личных диалогах и каналах рабочие команды недоступны.
- Постоянный кеш отчётов: 5 минут для полного отчёта, 1 минута для неполного. Профиль и история проверяются перед cache lookup.
- FACEIT-команды не отправляют промежуточные сообщения, карточки или новые кнопки «Продолжить»: успех — одна итоговая PNG, ошибка или исчерпание бюджета — один безопасный текстовый отказ. Короткий `Retry-After` ожидается автоматически в пределах рабочего бюджета; в облаке на работу отведено 65 секунд из общего 90-секундного бюджета обработчика, с резервом для конечного ответа.

## Проверки

Нужен Node.js 24. Тесты используют синтетические данные и не отправляют сообщения в рабочий Telegram-чат. Локальная операторская CLI использует macOS (`/usr/sbin/lsof` для проверки identity процесса): её полный suite в CI запускается на `macos-15`. Облачный suite и сборка запускаются на Linux.

```bash
cd faceit-telegram-bot
npm ci
npm test
npm run check
cd ../faceit-telegram-bot-sites
npm ci
npm test
npm run build
```

Облачным тестам и сборке нужен локальный loopback для workerd/Miniflare; настоящие секреты не требуются. Контрольный набор актуального снимка: 379 локальных и 73 облачных теста, всего 452.

## Безопасность и запуск

Секреты, SQLite/D1-данные, настройки TeamSpeak, generated `private-settings.js`, зависимости, build outputs и старая Git-история в импорт не включены. Новый clone не содержит ключей и не должен автоматически запускать бота.

В коде сохранены не являющиеся секретами настройки существующего deployment: имя бота и Sites project ID. Для своего экземпляра нужны отдельный бот и свои ключи. ID в документации — диагностические примеры, не условия допуска. Никогда не тестируйте polling на токене production-бота при активном webhook.

Добавить бота может любой владелец группы. TeamSpeak и личные FACEIT-привязки разделены по chat ID; `/setts` по-прежнему доступен только администратору текущей группы, остальные рабочие команды — её действующим участникам. Открытый доступ увеличивает общий расход FACEIT API и хостинга: ограничения заданий и обработка rate limit остаются, но отдельная квота или гарантированная скорость для каждого чата не обещаются.

`faceit-telegram-bot-sites/.openai/hosting.json` относится к существующему рабочему Sites. Push в GitHub и merge PR **не публикуют** код и не меняют webhook. Развёртывание выполняет владелец отдельным проверенным процессом Sites; автоматического deploy workflow здесь нет.

Исторические инструкции в подпапках описывают прежнее расположение на Mac владельца; абсолютные пути в документации нужно адаптировать к своему checkout.

## Изменения относительно исходного снимка

- Проверка `scripts/check.mjs` допускает отсутствие единственного ожидаемого generated `private-settings.js`; все другие пропавшие импорты остаются ошибкой.
- Helper переноса секретов использует относительную соседнюю папку вместо личного абсолютного пути.
- Добавлена CI-проверка macOS local / Linux cloud без production-секретов и без публикации.

Сторонние лицензии сохранены в подпапках. Собственная open-source лицензия пока не выбрана.
