# FACEIT CS2 Telegram bot

Приватный репозиторий текущего кода `road_to_3_elo_bot`: локальный резерв, адаптер Telegram Serverless и работающая копия Sites/Cloudflare Workers.

## Структура

- `faceit-telegram-bot/` — локальный Node.js runner, операторская CLI, переносимое ядро, Telegram Serverless и подробная документация.
- `faceit-telegram-bot-sites/` — текущая облачная реализация: webhook, D1, PNG FACEIT Dark и постоянный кеш отчётов/Telegram file_id.

Папки намеренно оставлены соседями: CLI переключения использует такой layout. Это импорт текущих реализаций с добавленными личными FACEIT-привязками, без большого рефакторинга; ядро пока дублируется. Новый GitHub-репозиторий не заменяет автоматически исходный репозиторий публикаций Sites.

## Возможности

- `/last [ник]` — последний завершённый матч CS2, картинка FACEIT Dark.
- `/stats [ник]` — последние до 30 матчей, картинка FACEIT Dark.
- `/setfaceit ник` — личный FACEIT в текущем чате; `/setfaceit` — показать, `/unsetfaceit` — удалить. Без аргумента `/last` и `/stats` используют эту привязку, явный ник её не меняет.
- `/setts адрес:порт пароль` и `/ts` — зашифрованные настройки TeamSpeak только своей группы.
- `/poll` — неанонимный опрос времени игры с множественным выбором.
- `/menu`, `/setup` и inline-кнопки.
- Постоянный кеш отчётов: 5 минут для полного отчёта, 1 минута для неполного. Профиль и история проверяются перед cache lookup.

## Проверки

Нужен Node.js 24. Тесты используют синтетические данные и не отправляют сообщения в рабочий Telegram-чат. Локальная операторская CLI использует macOS (`/usr/sbin/lsof` для проверки identity процесса): её полный suite в CI запускается на `macos-15`. Облачный suite и сборка запускаются на Linux.

```bash
cd faceit-telegram-bot
npm ci
npm test
npm run check
cd ../faceit-telegram-bot-sites
npm ci
npm test
npm run build
```

Облачным тестам и сборке нужен локальный loopback для workerd/Miniflare; настоящие секреты не требуются.

## Безопасность и запуск

Секреты, SQLite/D1-данные, настройки TeamSpeak, generated `private-settings.js`, зависимости, build outputs и старая Git-история в импорт не включены. Новый clone не содержит ключей и не должен автоматически запускать бота.

В коде сохранены не являющиеся секретами настройки существующего deployment: имя бота, default allowlist и Sites project ID. Для своего экземпляра нужны отдельный бот, свои ключи и разрешённые chat ID. Никогда не тестируйте polling на токене production-бота при активном webhook.

`faceit-telegram-bot-sites/.openai/hosting.json` относится к существующему рабочему Sites. Push в GitHub и merge PR **не публикуют** код и не меняют webhook. Развёртывание выполняет владелец отдельным проверенным процессом Sites; автоматического deploy workflow здесь нет.

Исторические инструкции в подпапках описывают прежнее расположение на Mac владельца; абсолютные пути в документации нужно адаптировать к своему checkout.

## Изменения относительно исходного снимка

- Проверка `scripts/check.mjs` допускает отсутствие единственного ожидаемого generated `private-settings.js`; все другие пропавшие импорты остаются ошибкой.
- Helper переноса секретов использует относительную соседнюю папку вместо личного абсолютного пути.
- Добавлена CI-проверка macOS local / Linux cloud без production-секретов и без публикации.
- Тест wrapper использует синтетический HOME с Node.js, а не установку на личном Mac владельца.

Сторонние лицензии сохранены в подпапках. Собственная open-source лицензия пока не выбрана; репозиторий приватный.
