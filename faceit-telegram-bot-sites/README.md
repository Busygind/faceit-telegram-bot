# Road to 3 ELO — облачная копия

Sites-развёртывание Telegram-бота FACEIT CS2. Исходный проект `/Users/busygind02/IdeaProject/faceit-telegram-bot` сохранён как локальный резерв.

## Выполнение

- Cloudflare Workers через Sites/Vinext; облачная D1 отделена от локальной SQLite.
- `/api/telegram/webhook` принимает только защищённые JSON POST; тело ограничено, сырые Telegram update и реквизиты TeamSpeak не логируются и не ставятся в очередь.
- `/api/health` показывает только признаки готовности, без ключей и данных чата.
- `/last` и `/stats` возвращают только сжатые изображения FACEIT Dark. TeamSpeak шифруется и привязан к чату. Настройки опроса сохранены.
- Прогресс отчёта сохраняется каждые четыре чтения FACEIT. Между пакетами действует мягкая граница 25 секунд; при паузе FACEIT или достижении границы отправляется изображение с кнопкой «Продолжить».
- Все исходящие HTTP-запросы одного webhook имеют общий жёсткий бюджет **90 секунд с момента входа webhook**, включая чтение тела и ожидание D1. По истечении срока текущие HTTP-запросы прерываются, новые не запускаются, даже если ожидание БД завершилось позднее. Контроллеры разных update независимы; ограниченный кеш завершённых матчей сохраняется между запросами.
- Обработчик всегда ожидается до ответа; фонового подтверждения или произвольных фоновых заданий нет. Уже принятый Telegram запрос при сетевом обрыве может иметь неизвестный результат: распределённую exactly-once доставку HTTP не гарантирует.

## Личный FACEIT

`/setfaceit ник` проверяет существование профиля CS2 и сохраняет FACEIT player ID + ник для пары Telegram `chat_id/user_id`. `/setfaceit` показывает свою сохранённую настройку, `/unsetfaceit` удаляет её. Админские права пользователя не нужны; доступен только собственный профиль настройки и только участникам разрешённой группы.

`/last` и `/stats` без аргумента используют личную привязку отправителя; явный ник работает как раньше и её не изменяет. Кнопки статистики используют аккаунт нажавшего участника, не автора меню. Команды и ошибки статистики остаются только картинками FACEIT Dark. Подробности: [пользовательский путь](../faceit-telegram-bot/docs/personal-faceit-ru.md).

Новая D1-миграция `0002_player_links.sql` добавляет таблицу и уникальный индекс пары chat/user. Старые миграции не меняются. Привязки не входят в TTL очистку кеша/отчётов, не логируются и сохраняются после перезапуска. При смене chat ID (например, basic group → supergroup) привязку нужно задать заново. Базы local/Sites по-прежнему отдельные.

## Постоянный кеш карточек

Готовые отчёты и Telegram `file_id` хранятся в D1 (`report_cache`), отдельно от временного RAM-кеша подробностей завершённых матчей. Поэтому быстрый путь работает и при новом Worker isolate. Миграция `0001_smooth_sunset_bain.sql` добавляет таблицу и индекс; миграцию `0000` менять нельзя.

- Перед каждым cache lookup бот заново читает профиль FACEIT и полностью выбирает актуальные последние 1/30 матчей из истории. Новый матч, изменившиеся метаданные выборки, ник, текущие ELO/уровень, ключи или версия рендерера меняют ключ кеша.
- Срок свежести полного отчёта — 300 секунд, неполного — 60 секунд от генерации. Повторное чтение или сохранение `file_id` срок не продлевают. Отметка обновления на картинке остаётся исходной.
- На попадании не создаётся новый job и не загружаются details/stats каждого матча. При наличии `file_id` нет ни рендеринга, ни повторной загрузки PNG в Telegram.
- Только явный отказ Telegram принять сохранённый идентификатор разрешает одну повторную отправку картинки байтами. При сетевой неопределённости, 429, 5xx или другом отказе слепого повтора нет.
- Ошибки кеша не препятствуют обычному расчёту. Хранится не более 256 записей на БД, просроченные удаляются при записи. Сырые команды, сообщения и реквизиты TeamSpeak не попадают в кеш.
- Локальный резерв имеет аналогичный кеш в своей SQLite; базы и `file_id` между средами автоматически не копируются. Адаптер будущего Telegram Serverless пока использует прежний путь без этого постоянного кеша.

Первый запрос после истечения срока или нового матча по-прежнему холодный. Даже на попадании остаются свежие FACEIT-запросы, проверки доступа, D1 и отправка Telegram: мгновенная доставка не гарантируется.

Санитизированные события `BOT_REPORT_CACHE` и `BOT_REQUEST_METRICS` показывают hit/miss, возраст, число запросов, рендеров и загрузок без ников, chat ID, ключей и текстов сообщений. `faceitReads` считает логические чтения API, в том числе обслуженные RAM-кешем. При тёплом пути ожидаются `renderCount=0`, `photoUploads=0`, `photoFileReuses=1`.

## Секреты

Четыре значения `BOT_TOKEN`, `FACEIT_API_KEY`, `TS_ENCRYPTION_KEY`, `WEBHOOK_SECRET` уже перенесены в штатные секреты Sites зашифрованным каналом без вывода значений в переписку. В исходниках, клиентском bundle и `.openai/hosting.json` ключей нет. Имена перечислены в `.env.example`.

Исходные защищённые файлы остались на Mac. Облачные ключи шифрования и webhook сохранены в игнорируемом `.secrets/cloud-generated.json` с правами 0600. Не удаляйте ключ шифрования после сохранения облачных настроек TeamSpeak. После изменения секретов в Sites требуется повторное развёртывание, чтобы применить новую ревизию окружения.

Резервный ручной способ — `node scripts/copy-cloud-secret.mjs ИМЯ_СЕКРЕТА`: он копирует одно значение в буфер обмена, не печатая его; вставлять только в соответствующее секретное поле Sites. Никогда не отправляйте ключи в чат или исходники.

## Переключение одной командой

Команды выполняются из **исходного локального проекта**, не из облачной копии:

```bash
export PATH="/Users/busygind02/.local/bin:$PATH"
cd /Users/busygind02/IdeaProject/faceit-telegram-bot
npm run bot -- status
npm run bot -- cloud
npm run bot -- local
```

- `status` проверяет текущий режим, локальный процесс и готовность облака, ничего не переключает.
- `cloud` сначала проверяет облако и секрет webhook, корректно останавливает подтверждённый локальный процесс, затем включает webhook. Очередь Telegram не удаляется. При неопределённом результате команда не запускает второй потребитель автоматически.
- `local` отключает только наш webhook, сохраняет очередь и ждёт 150 секунд для завершения уже принятых облачных запросов; затем запускает локальный процесс. Это намеренная пауза безопасности, а не зависание. После облачного 90-секундного egress-предела новые исходящие запросы старого обработчика запрещены.

Не запускайте polling и webhook одновременно. Переключение лучше выполнять, когда никто не вызывает команды бота: при обрыве уже принятой Telegram операции её результат может остаться неизвестным; последний ответ иногда может повториться между раздельными БД. Проверяйте `status` после прерванного или неудачного переключения.

Локальные настройки TeamSpeak и локальный ключ шифрования в облако не переносились. Настройте облачный TeamSpeak командой `/setts` в той же группе; резерв сохраняет прежние настройки. Последующие изменения между БД автоматически не синхронизируются.

## Проверка

```bash
npm test
npm run build
```

Тесты используют синтетические ключи, SQLite в памяти как D1 double, подменённый HTTP и настоящий PNG-рендеринг. Дополнительно настоящий workerd с native D1 проверяет хранение отчёта между запросами, `node:crypto`/`Buffer`, сохранение `file_id` и фиксированный TTL. Они не отправляют сообщения в Telegram. При публикации Sites применяет сгенерированные миграции схемы. Реальные квоты и доставка требуют проверки развёрнутого бота в разрешённой группе.

## Cloudflare transport compatibility

The cloud transport uses `redirect: manual` and rejects every 3xx response without following Location. Workerd rejects Node-style `redirect: error` before network I/O; the shared Node adapter remains unchanged, and the cloud boundary overrides that option. A real-workerd regression test covers this difference in addition to mocked HTTP tests. Diagnostics contain only whitelisted codes, never raw updates, URLs, error messages or credentials.
