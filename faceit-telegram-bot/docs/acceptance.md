# Приёмка

## Локальная

Автоматизированные проверки работают без сети/ключей:

```bash
npm test
npm run check
npm run demo
```

Покрытие: история 0/1/29/30/31, старая история и неупорядоченные страницы, лимиты pagination/split, 429 и восстановление, отменённые/идущие/чужие игры, BO3, metric coverage, отсутствие stats, AES-GCM-SIV RFC vectors/tamper/другой chat, SQLite CAS/migration/lease, весь групповой путь, точный poll JSON, ambiguous POST без retry, PNG/text и длинные Unicode строки. Для обеих команд есть демонстрационные FACEIT Dark PNG на синтетических данных; визуальная и автоматическая проверки фиксируются в `verification.md`.

Фактическое число тестов и итог финальной проверки фиксируются в `verification.md`. Проверка SDK импортов статическая, а не доказательство исполнения в реальном Telegram V8.

## Облачная — ещё НЕ выполнена

Нужны Serverless CLI доступ, FACEIT key, тестовый публичный ник и группы A/B/C. Не заменять этот список mock-тестами:

- [ ] В BotFather Serverless действительно доступен и включён; проверить условия/стоимость и лимиты.
- [ ] Login, код deploy, schema migrate и webhook sync без ошибок.
- [ ] Проверить фактический SDK raw SQL, PNG InputFile, размер modules, Unicode atlas и время/память invocation.
- [ ] FACEIT key читает профиль, CS2 history/details/stats. Проверить значение границ from/to и фактическую структуру stats на реальном матче.

- [ ] A/B с одним администратором: разные TS, изменение A не меняет B; C ненастроена; private и пересылка ничего не читают/не меняют.
- [ ] Участник не меняет TS; анонимный админ не меняет; после удаления/отзыва прав доступ закрыт.
- [ ] Пароль с пробелами, --no-password, неверный порт; прежняя запись сохраняется; source message удаляется при праве и предупреждение при отказе.
