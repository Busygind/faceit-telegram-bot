## 2. Что означает «приложение FACEIT»

Это запись о нашем проекте в кабинете разработчика FACEIT, а не отдельная программа, которую нужно установить. Внутри этой записи создаётся ключ, которым бот будет представляться API. У одного приложения может быть несколько ключей. [Создание приложения](https://docs.faceit.com/getting-started/intro/start-here/).

| Секрет | Где появляется | Нужен нашему проекту |
|---|---|---|
| Telegram Bot API token | BotFather при создании бота | Для локального runner нужен файл `.secrets/telegram-bot.token`; в облачном Serverless Bot API авторизует SDK платформы |
| Telegram Serverless CLI Access token | BotFather → выбранный бот → Serverless → CLI Access | Да, но только после выдачи Serverless-доступа; вводится в CLI login |
| FACEIT Server side API Key | FACEIT Developer Portal → приложение → API Keys | Да, для чтения публичных профилей, истории и статистики |

**Ни один из этих секретов не присылай в Telegram или в этот чат.** Мне достаточно пути к локальному защищённому файлу с ключом FACEIT.

## 3. Создать приложение в FACEIT

1. Открой [FACEIT Developer Portal](https://developers.faceit.com/) в браузере.
2. Нажми **Login** и войди своим обычным FACEIT-аккаунтом. Отдельный аккаунт для бота не требуется. Пароль от аккаунта нигде, кроме официального входа FACEIT, вводить не нужно.
3. Перейди в раздел **App Studio**.
4. Создай новое приложение. Точное расположение и название кнопки зависят от текущего интерфейса портала; ищи создание новой App внутри App Studio.
5. Для карточки приложения предлагаю такие значения:

   | Поле | Значение |
   |---|---|
   | Name / название | `Road to 3 ELO` |
   | Description / описание | `Private Telegram bot showing public FACEIT CS2 match results and player statistics for a group of friends.` |
   | Website / ссылка, если поле доступно и принимает ссылку на бота | `https://t.me/road_to_3_elo_bot` |

6. Сохрани приложение и открой его страницу с деталями.

Логин личным FACEIT-аккаунтом и раздел App Studio подтверждены [официальным руководством](https://docs.faceit.com/getting-started/intro/start-here/). Название, описание, иконка и ссылка относятся к идентификации приложения; документация не подтверждает, что все эти поля обязательны. Для нашей функции не нужно заранее настраивать публикацию в каталоге FACEIT или придумывать данные компании. [Карточка приложения](https://docs.faceit.com/docs/).

Если портал потребует неожиданное обязательное поле, проверку аккаунта или согласование, не заполняй его наугад. Пришли название поля или скриншот **без ключей и личных данных** — разберём конкретный экран. Мгновенную выдачу ключа со стороны FACEIT я не обещаю.

## 4. Создать правильный API Key

1. На странице созданного приложения открой **API Keys**.
2. Выбери создание нового ключа.
3. В типе ключа выбери **Server side**, не **Client side**.
4. Если просят понятную метку ключа, можно указать `road-to-3-elo-server`.
5. Создай ключ и скопируй его значение. Дальше сразу сохраним его в защищённый файл.

Почему Server side, если код написан на JavaScript? Важен не язык, а **место выполнения**: наш JavaScript исполняется на серверной стороне Telegram, а не в браузерах участников. Пользователи не должны получать ключ. FACEIT различает Server side и Client side именно по этому принципу. [Типы API-ключей](https://docs.faceit.com/getting-started/authentication/api-keys/).

Для публичных данных Data API достаточно ключа приложения: вход друзей через FACEIT OAuth, их пароли, Steam cookies, Client Secret и Redirect URI нашему боту не требуются. [Авторизация Data API](https://docs.faceit.com/docs/data-api/).

## 5. Безопасно сохранить FACEIT key на Mac

1. Открой Terminal и сначала выполни подготовку:

```bash
cd /Users/busygind02/IdeaProject/faceit-telegram-bot
mkdir -p .secrets
chmod 700 .secrets
```

2. Скопируй и запусти следующий блок. Он остановится и будет ждать Enter — **ключ пока не копируй**:

```bash
(
  umask 077
  set -o noclobber
  printf 'Скопируй значение ключа в FACEIT, вернись сюда и нажми Enter. Сам ключ в терминал не вставляй.\n'
  IFS= read -r confirmation && pbpaste > .secrets/faceit.key
) && chmod 600 .secrets/faceit.key
```

3. Пока команда ждёт, перейди в FACEIT и скопируй **только значение ключа**, без `Bearer`, кавычек или его названия. Вернись в Terminal и нажми Enter, **не вставляя ключ в терминал**. Команда запишет буфер как данные и откажется перезаписывать существующий файл. Такой порядок важен: если скопировать текст команд уже после ключа, в буфере вместо ключа окажутся команды. Если нужно отменить, нажми Ctrl+C.

4. Проверь только права и наличие непустого файла, **не его содержимое**:

```bash
stat -f '%Sp %N' .secrets/faceit.key
test -s .secrets/faceit.key && echo 'Файл непустой' || echo 'Файл пустой: ключ не сохранён'
```

Ожидаемые права файла: `-rw-------`. Эта проверка не доказывает, что ключ рабочий, — только что файл существует и не пуст.

После успешного сохранения можно очистить текущий буфер командой `printf '' | pbcopy`; история стороннего менеджера буфера при этом не очищается. Если файл уже существует, не удаляй его вслепую. Не печатай ключ через `cat`, `echo` и не передавай его аргументом shell-команды. `.secrets/` исключена из Git, но это не шифрование.

После сохранения напиши только: «Ключ сохранён в `/Users/busygind02/IdeaProject/faceit-telegram-bot/.secrets/faceit.key`». Тогда можно отдельно проверить доступ к публичному профилю `aghori-`; ожидание Telegram Serverless этому не мешает. 16 октября 2026 года такая проверка уже выполнена: для `aghori-` доступны профиль, CS2-история и статистика последнего матча. Значение ключа в вывод не попадало.

3. Открой новый Terminal и проверь `node --version` и `npm --version`. У Node ожидается `v24…`.
4. Выполни:

```bash

```

`npm ci` установит зафиксированные инструменты разработки. Тесты используют синтетические данные и не отправляют команды в твою группу. Успешные тесты ещё не означают, что код развёрнут или реальный FACEIT key принят.

## 8. После выхода из листа ожидания Telegram Serverless

Этот раздел выполняется **только когда BotFather действительно предоставит Serverless-доступ боту**, а не сразу после подачи заявки. До подключения webhook останови локальный runner через `Ctrl+C`: polling и webhook одновременно не работают. Локальные TS настройки автоматически не мигрируют; после перехода снова используй `/setts` в группе.

### 8.1. Авторизовать CLI

1. Открой [BotFather](https://t.me/BotFather), выбери `road_to_3_elo_bot`.
2. Открой **Serverless → CLI Access** и получи **Access token**.
3. В Terminal выполни:

```bash
cd /Users/busygind02/IdeaProject/faceit-telegram-bot
npx tgcloud login
```

4. Вставь Serverless CLI token в интерактивный запрос CLI, **не в строку shell и не в этот чат**. Папку `.tgcloud/` не открывай и не присылай: ею управляет CLI. [Документация платформы](https://core.telegram.org/bots/serverless).

### 8.2. Настроить FACEIT и единственный разрешённый чат

```bash
cd /Users/busygind02/IdeaProject/faceit-telegram-bot
npm run configure -- \
  --faceit-key-file /Users/busygind02/IdeaProject/faceit-telegram-bot/.secrets/faceit.key \
  --chat-id -1004393474895
```

Команда читает ключ из файла, создаёт защищённую конфигурацию и случайный ключ шифрования TeamSpeak. При повторном запуске исходный ключ шифрования сохраняется. **Не удаляй `.secrets/runtime.json`**: без него сохранённые пароли TeamSpeak могут стать нечитаемыми.

Сделай отдельную зашифрованную резервную копию `.secrets/runtime.json` в своём менеджере секретов или другом защищённом месте. В нём находятся секреты, поэтому не прикладывай его к сообщениям.

Параметры `--chat-id` задают весь разрешённый список. Сейчас используем только `-1004393474895`; функции других групп запрещены. Публичный nickname не запоминается за участником или группой — его по-прежнему нужно указывать в каждой FACEIT-команде.

### 8.3. Проверить конфигурацию и опубликовать код

```bash
npm run deploy -- --dry-run
npm run deploy
```

Первая команда проверяет локальную готовность **без загрузки**. Вторая действительно загружает серверный код в Telegram. Если есть ошибка — остановись на ней, не переходи сразу к следующему шагу.

### 8.4. Создать схему базы данных

```bash
npx tgcloud migrate --dry-run
npx tgcloud migrate
```

Сначала посмотри план миграции, затем подтверди обычную миграцию. Для первой установки ожидается создание таблиц проекта; неожиданные удаления или изменения чужих данных требуют разбора. Загрузка кода сама по себе базу не создаёт. Не используй `--yes` или принудительное применение ради обхода предупреждений.

### 8.5. Подключить Telegram updates

```bash
npx tgcloud webhook sync
npx tgcloud webhook
```

Теперь платформа должна направлять сообщения и нажатия кнопок обработчикам проекта. Домен, HTTPS-сертификат, VPS, Docker и постоянно запущенный локальный процесс для выбранного варианта не нужны. Фактические квоты, стоимость и условия Serverless нужно проверить при предоставлении доступа, а не считать бесплатность гарантированной.

## 9. Полностью проверить путь участника

Все команды ниже отправляй **в тестовой группе**, а не в личном диалоге с ботом. Суффикс `@road_to_3_elo_bot` убирает неоднозначность, если в группе несколько ботов.

| Отправить в группе | Ожидаемый результат |
|---|---|
| `/setup@road_to_3_elo_bot` | ID `-1004393474895` и состояние настройки |
| `/menu@road_to_3_elo_bot` | Кнопки и регистрация slash-команд |
| `/last@road_to_3_elo_bot aghori-` | PNG последнего завершённого CS2-матча в FACEIT Dark, дата по Москве, результат, счёт, составы и кнопка со ссылкой |
| `/stats@road_to_3_elo_bot aghori-` | До 30 матчей, карточка FACEIT Dark и текст; при необходимости кнопка «Продолжить» |
| `/poll@road_to_3_elo_bot` | «Играть сегодня (время по МСК)», девять вариантов от «да, в 17» до «нет» |

Локально порции догружаются автоматически. В Serverless или при защитной паузе «Продолжить» нажимай в том же чате и теме: прогресс уже сохранён. Недостающие данные должны быть помечены; задержка статистики последнего матча не должна приводить к его подмене старым.

В опросе выбери несколько вариантов и измени голос. Голоса должны быть открытыми, добавление вариантов, таймер и автоматическое закрытие выключены.

### TeamSpeak только этой группы

Администратор группы отправляет прямо в ней:

```text
/setts@road_to_3_elo_bot ts.example.org:9987 пример пароля с пробелами
```

Это **пример**, замени адрес и пароль своими. Участники получают сохранённые реквизиты командой `/ts@road_to_3_elo_bot`. Если сервер действительно без пароля, администратор использует отдельную форму `/setts@road_to_3_elo_bot --no-password ts.example.org:9987`.

Данные закрепляются по ID текущей группы; вводить ID в самой `/setts` не нужно. В личном диалоге настройка не принимается. Настройки не становятся глобальными для других групп, даже если у них тот же администратор.

**Внимание:** команда с реальным паролем видна группе и Telegram. После успешного сохранения бот пытается удалить исходное сообщение; если прав не хватает, он должен предупредить. Удаление не отменяет уведомления, пересылки или скриншоты. В локальные shell-команды и диагностические логи пароль TeamSpeak вводить не нужно.

## 10. Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Бот совсем не отвечает | В локальном режиме запущен `npm run local`, Mac не спит? В облачном режиме выдан доступ и выполнены deploy/migrate/webhook sync? Команда отправлена в разрешённой группе? |
| `node` или `npm`: command not found | Установить Node 24 LTS и открыть новый Terminal |
| configure отказывается читать key file | Файл должен быть обычным файлом с правами `0600`, не symlink; проверить только `stat`, не печатать ключ |
| FACEIT сообщает об авторизации | Проверить тип Server side и отсутствие `Bearer`/кавычек внутри файла; при утечке перевыпустить ключ в FACEIT |
| После нескольких запросов появилась пауза | При rate limit дождаться указанного времени и использовать «Продолжить»; не спамить командами |
| Нельзя сохранить TeamSpeak | Команду отправляет реальный администратор группы, не анонимный администратор; у бота есть права проверки членства |

Не публикуй полный CLI diff/pull/reset и содержимое generated private settings: серверный модуль конфигурации содержит ключи. Это не отдельный Vault; люди с доступом к облачным исходникам могут прочитать серверную конфигурацию.

Подробные технические ограничения, резервирование и обновления описаны в [deployment.md](deployment.md), критерии проверки — в [acceptance.md](acceptance.md). Это дополнительные справочники; для первого запуска начинай с этой инструкции.
