# Переключение бота между Sites и Mac

Две копии используют один Telegram-токен. Активна только одна доставка updates: облачный webhook **либо** локальный long polling. Код и базы остаются в обеих папках. CLI не публикует исходники и не меняет секреты Sites.

## Команды

Открой каталог проекта. Обёртка сама найдёт установленный Node.js, менять PATH не нужно:

```bash
cd ~/IdeaProject/faceit-telegram-bot
./bot status
```

Включить облачную версию:

```bash
./bot cloud
```

Вернуть бота на Mac:

```bash
./bot local
```

Это три отдельных действия, не последовательность для копирования целиком. Если Node.js уже есть в PATH, сохраняется npm-альтернатива: `npm run bot -- status`, `npm run bot -- cloud`, `npm run bot -- local`.

Локальная команда сама запускает отделённый процесс и дожидается `POLLING_READY`. После её успешного завершения терминал можно закрыть. Mac по-прежнему должен работать, не спать и иметь интернет. Перезагрузка Mac останавливает эту версию; автозапуска при входе нет. Приватный лог: `.local-data/local-runner.log`.

При переходе из облака на Mac команда выводит `DRAINING_CLOUD` и ждёт **150 секунд**, чтобы уже принятый облаком запрос успел закончиться. Это защитный запас по сетевым таймаутам, не гарантия отсутствия повторной доставки Telegram. Если прервать команду через `Ctrl+C`, webhook уже будет удалён, а локальный процесс ещё не запущен. CLI освободит свои lock-файлы, сохранив deadline ожидания; повтори `./bot local`, и она доождётся остатка интервала. Очередь Telegram не сбрасывается. Во время других критических действий сигнал прерывания ждёт безопасной точки.

## Что требуется для облака

Облачная копия: `https://road-to-3-elo-bot.aghori-db.chatgpt.site`, endpoint `/api/telegram/webhook`. До переключения она должна быть опубликована, миграции применены, а четыре секрета — внесены в Sites и активированы публикацией:

- `BOT_TOKEN` — тот же бот, что в локальном защищённом файле.
- `FACEIT_API_KEY` — ключ FACEIT.
- `TS_ENCRYPTION_KEY` — собственный ключ облачной базы.
- `WEBHOOK_SECRET` — защитный заголовок Telegram webhook.

CLI читает токен из `.secrets/telegram-bot.token`, ключ FACEIT из `.secrets/faceit.key`, а `WEBHOOK_SECRET` — из соседнего файла `../faceit-telegram-bot-sites/.secrets/cloud-generated.json`. Файлы должны быть обычными, без symlink и без доступа группы/остальных (`0600`). Их содержимое в терминал, командную строку и переписку не выводится.

Перед остановкой локального процесса CLI проверяет имя Telegram-бота, защищённый `POST /api/health` с `WEBHOOK_SECRET`: он реально выполняет запрос к облачной базе и Telegram `getMe`, проверяет ожидаемое имя бота и должен вернуть `ready`, `database`, `telegram`, `expectedBot`, равные `true`. Сообщений в чат проверка не отправляет; одних признаков наличия конфигурации недостаточно. Неготовое облако или неправильный секрет оставляют локальную версию работающей.

## Защита переключения

- Чужой webhook не удаляется и не заменяется: `SWITCH_FOREIGN_WEBHOOK`.
- Локальный процесс останавливается только после проверки PID из lock-файла, команды запуска, настоящего Node executable, рабочей директории и времени старта. Никаких `pkill node` или `SIGKILL`.
- После остановки Mac CLI подтверждает в Telegram только updates ниже сохранённого SQLite `next_offset` через неблокирующий `getUpdates`. Полученный новый update не обрабатывается и остаётся в очереди для webhook. Это предотвращает повтор последней уже подтверждённой локальной порции в независимой облачной базе.
- На время изменений webhook удерживаются операторский и polling lock. `drop_pending_updates` всегда `false`, облачный `max_connections` — `1`.
- Если `setWebhook` не удался и Telegram достоверно подтвердил пустой webhook, ранее работавший локальный процесс запускается снова: `SWITCH_CLOUD_FAILED_LOCAL_RESTORED`.
- Если результат облачного переключения неизвестен, локальный polling **не** запускается: `SWITCH_CLOUD_UNCERTAIN`. Дождись восстановления Telegram API, выполни `status`, затем повтори нужную команду.
- Ошибка запуска Mac после удаления webhook оставляет очередь в Telegram. Исправь проблему и повтори `local`; автоматической передачи в потенциально неработающее облако нет.

`status` возвращает только режим, локальный PID и признак готовности облака после той же защищённой проверки зависимостей. Если локального webhook-secret нет, `cloudReady` будет `false` — наличие переменных окружения не считается подтверждением работоспособности. `foreign-webhook` означает внешний endpoint, `conflict` — обнаруженный локальный процесс при активном нашем webhook; `offline` — ни одного известного потребителя. Проверка не способна обнаружить polling на другом компьютере: не запускай этот токен отдельно на другом хосте.

Повреждённые, небезопасные и устаревшие lock-файлы автоматически не удаляются. При `LOCAL_STALE_LOCK` или `SWITCH_STALE_LOCK` проверь владельца и убедись, что ни один процесс не жив; только затем вручную убирай соответствующий `.local-data/control.lock` или `polling.lock`. Ошибки сохраняют файл для разбирательства.

## Данные и ограничения

Переключается доставка Telegram, а **не данные**: локальная SQLite и облачная D1 независимы. TeamSpeak и незавершённые отчёты не синхронизируются. После перехода в другую среду настрой TS командой `/setts` в нужном чате. Не переноси сырую локальную базу с TS-паролем в публичные файлы сайта.

Передача updates Telegram — не распределённая транзакция: уже выполнявшийся запрос или повтор Telegram теоретически может завершиться на границе переключения. CLI сохраняет очередь и не обещает exactly-once между разными базами. Из облака в локальную версию предусмотрена пауза; её deadline хранится в `.local-data/cloud-drain.json` и учитывается после прерывания.
