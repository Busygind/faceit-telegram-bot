# Проектирование Telegram бота для FACEIT CS2

Актуализация требований: 16 октября 2026 года. Выбран JavaScript + Telegram Serverless; проект реализован в `/Users/busygind02/IdeaProject/faceit-telegram-bot`.

Бот для Telegram группы умеет настроить и выдать TeamSpeak, запустить нативный опрос «Играть сегодня (время по МСК)» и получить два вида FACEIT отчётов по переданному нику: обзор последнего завершённого CS2 матча и статистику последних 30 завершённых матчей. Регистрация участников, привязки Telegram к FACEIT, списки игроков и совместная статистика отложены и не входят в первую версию.

## Команды и кнопки

| Кнопка | Команда | Результат |
|---|---|---|
| Главное меню | `/menu`, `/start` | Доступные действия и подсказки |
| Настройка | `/setup` | Статус готовности и инструкция настройки для администратора |
| Настроить TeamSpeak | `/setts <IP:порт> <пароль>` | Сохранить реквизиты только для текущей группы |
| Получить TeamSpeak | `/ts` | Выдать реквизиты только этой группы |
| Играть сегодня | `/poll` | Создать опрос в текущей группе и текущей теме форума |
| Последний матч | `/last <ник>` | Обзор последнего завершённого FACEIT CS2 матча |
| Последние 30 матчей | `/stats <ник>` | Статистика последних 30 завершённых FACEIT CS2 матчей |
| Помощь | `/help` | Синтаксис команд и объяснение результата |

Статистику запрашивают `/last` и `/stats`; `/setfaceit ник` дополнительно читает только профиль для проверки личной настройки. Ник необязателен после `/setfaceit`; без аргумента используется личная привязка текущего чата, а не история сообщений или имя Telegram. Можно запросить любой публичный FACEIT профиль: принадлежность игрока Telegram группе не требуется. Обе команды поддерживают `/команда@bot_username <ник>`.

Если ник пропущен, бот отвечает подсказкой с синтаксисом. Ошибочный ник, отсутствие CS2, отсутствие завершённых матчей и временная ошибка API имеют разные сообщения. Кнопки меню FACEIT показывают, какую команду с ником нужно отправить; они не предлагают сохранённый список игроков. Служебные сообщения в личке объясняют, что рабочие команды выполняются в разрешённой группе.

Меню реализовать inline-кнопками и зарегистрированными slash-командами. Обработчики кнопок и команд используют одни сервисы. Настройку TeamSpeak разрешить администраторам, просмотр статистики/TeamSpeak и запуск опроса — действующим участникам группы. Видимость административной кнопки не заменяет проверку прав на сервере.

## Опрос об игре сегодня

`/poll` без аргументов отправляет настоящий Telegram poll, не сообщение с кнопками голосования. Заголовок и порядок вариантов фиксированы и не зависят от того, какие часы уже прошли:

**Играть сегодня (время по МСК)**

- да, в 17
- да, в 18
- да, в 19
- да, в 20
- да, в 21
- да, в 22
- да, в 23
- да, позже
- нет

Через [Telegram sendPoll](https://core.telegram.org/bots/api#sendpoll) передать девять InputPollOption объектов с этими текстами. Значимые параметры задавать явно:

```json
{
  "type": "regular",
  "is_anonymous": false,
  "allows_multiple_answers": true,
  "allows_revoting": true,
  "shuffle_options": false,
  "allow_adding_options": false,
  "hide_results_until_closes": false,
  "is_closed": false,
  "disable_notification": false,
  "protect_content": false,
  "allow_paid_broadcast": false
}
```

Ни quiz, ни добавление своих вариантов, ни перемешивание, ни скрытие результатов не включаются. `members_only` не включать, country_codes не задавать; quiz-поля, description и media не передавать. `open_period` и `close_date` не передавать: автоматического закрытия нет. Не закреплять опрос автоматически и не создавать его по расписанию.

Голоса неанонимные, множественный выбор и переголосование включены. Telegram сам обслуживает голосование и отображение участников; бот не хранит собственный список проголосовавших и их выбор. Нативный множественный выбор разрешает выбрать «нет» вместе со временем; дополнительную логику взаимоисключения не вводить.

Создание допускается только в текущем разрешённом group/supergroup. `chat_id` берётся из update, при наличии message_thread_id использовать текущую тему. Не отправлять опрос в личку, канал или другой чат по аргументу команды. Если у бота нет прав отправить опрос, объяснить требуемое право, не менять формат на самодельные кнопки.

Технически сохранять только update_id, chat_id, message_thread_id, poll_id/message_id и статус доставки. Повторная доставка одного update не должна порождать новый опрос; новая явная команда пользователя может создать ещё один. При сетевой неопределённости после возможной отправки не повторять sendPoll автоматически: отметить outcome_unknown и не обещать ровно однократную доставку.

## TeamSpeak строго для текущего чата

Администратор отправляет непосредственно в нужной группе:

```text
/setts 203.0.113.10:9987 <пароль>
```

Пароль — весь остаток после адреса, включая внутренние пробелы. IP/hostname проверять синтаксически, порт — 1–65535; сетевое соединение с введённым адресом не выполнять. Явная форма `/setts --no-password <IP:порт>` задаёт отсутствие пароля. Неполная обычная команда не удаляет старый пароль.

`/setts` без аргументов и кнопка настройки показывают синтаксис в этой же группе. Переход в личку не нужен. Проверить тип group/supergroup, allowlist и административный статус автора; затем атомарно сохранить реквизиты. Подтверждение — «TeamSpeak для этого чата обновлён», без повторения пароля. При ошибке старую запись не менять.

Инварианты изоляции:

- `teamspeak_settings.chat_id` — PRIMARY KEY. Все операции `save_settings(chat_id, ...)`, `get_settings(chat_id)` и cache требуют chat_id из текущего группового update.
- Один администратор в группах A и B не связывает их настройки: update A не меняет B, get B не возвращает A. Для ненастроенной C нет fallback на пользователя, общий default или другой чат.
- В личке `/setts` и `/ts` не изменяют и не читают групповые реквизиты. Целевой chat_id нельзя передать аргументом или взять из последнего выбранного чата.
- Для настройки игнорировать forwarded messages и edited_message. Проверять chat_id исходного сообщения кнопки и текущий callback context.
- Не хранить групповой пароль глобально или в env. Сохранять зашифрованный пароль отдельной строкой на чат; секрет шифрования приложения находится отдельно от базы.
- При миграции group → supergroup перенести настройку атомарно, прекратив выдачу по старому ID.

`/ts` читает только свою строку; если её нет, отвечает «В этом чате TeamSpeak ещё не настроен» и показывает путь к настройке. Изменения действуют без перезапуска.

Команда с паролем видна участникам и проходит через Telegram. После успешного сохранения бот пытается удалить исходное сообщение при наличии права; ошибка удаления не откатывает настройку. Удаление не защищает от уведомлений, пересылок и скриншотов. Значения секретов не попадают в логи, подтверждения и игровые карточки.

## FACEIT без регистрации игроков

Один Server side API Key приложения используется для публичных данных всех запрашиваемых игроков; пароли FACEIT/Steam и пользовательский OAuth не нужны. Источники: [авторизация Data API](https://docs.faceit.com/docs/data-api/) и [контракты методов](https://docs.faceit.com/docs/data-api/data/).

Базовый адрес — `https://open.faceit.com/data/v4`. Нужны методы:

- `/players?nickname=...` — разрешить переданный ник в player_id и проверить CS2.
- `/players/{player_id}/history?game=cs2` — найти завершённые матчи.
- `/matches/{match_id}` — статус, дата, составы, счёт и ссылка.
- `/matches/{match_id}/stats` — показатели игроков и карт.
- `/players/{player_id}` — текущие ELO и уровень; не выдавать их за изменение в матче.

Точные CS2 поля и доступность ADR/HS проверяются read-only запросом после получения ключа. Не обещать rating, KAST, swing или историческое изменение ELO без источника. Недокументированные API и скрейпинг не использовать.

Личная привязка хранится в `player_links` по `(chat_id,user_id)` с уникальным индексом. `/setfaceit ник` проверяет профиль CS2, `/setfaceit` показывает свою настройку, `/unsetfaceit` удаляет её. `/last` и `/stats` без аргумента разрешают профиль по сохранённому FACEIT player_id; явный ник имеет приоритет без изменения настройки. Это не список членов чата и не доказательство владения FACEIT. Нет админской команды изменения чужой привязки. При смене chat ID привязку задают заново.

### Обзор последнего матча

`/last <ник>` выбирает последний завершённый CS2 матч по времени завершения. Текущие и отменённые игры не подменяют его.

Обзор содержит:

- Ник, дату и время по Europe/Moscow, карту или карты серии.
- Победу/поражение для команды выбранного игрока и счёт с явно обозначенными сторонами.
- Его K/D/A, K/D, K/R, ADR и HS при наличии исходных данных.
- Составы команд и доступные показатели игроков; неподтверждённые поля не выдумывать.
- Кнопку FACEIT matchroom и кнопку возврата в меню.

Первый формат обзора — компактный текстовый отчёт, при необходимости несколькими сообщениями. Когда подробные stats ещё не опубликованы, показать доступные сведения именно последнего матча и пометку об отсутствии деталей; не подменять его более старым матчем.

### Статистика последних 30 матчей

`/stats <ник>` выбирает до 30 самых новых завершённых CS2 матчей. Это не 30 дней и не lifetime агрегат. При меньшем числе игр показать фактический размер выборки. Отсутствие подробных stats не заменять более старым матчем ради полного покрытия.

Выводить число матчей, побед/поражений, процент побед, последние пять результатов, средние и суммарные убийства, K/D, K/R, доступные ADR/HS и разрез карт. Текущие ELO/уровень помечать «сейчас». Для BO3/BO5 сначала собрать карты в один матч; в разрезе карт считать сыгранные карты отдельно.

Считать из исходных сумм на одинаковом доступном срезе:

- `K/D = сумма убийств / сумма смертей`.
- `K/R = сумма убийств / сумма сыгранных раундов`.
- `Средние убийства = сумма убийств / число матчей с доступными убийствами`.
- `HS = 100 × сумма убийств в голову / сумма убийств`.
- `ADR = сумма урона / сумма раундов`; при наличии только ADR карты использовать взвешенное по её раундам значение с соответствующей пометкой.
- `Win rate = 100 × победы / матчи с известным результатом`; неизвестные результаты показывать отдельно.

У каждой метрики собственное покрытие; деление на ноль и отсутствие поля дают «—», не ноль. Не усреднять готовые K/D и не смешивать знаменатели разных доступных выборок.

### Выборка и ограничения истории

Зафиксировать время среза to. Всегда передавать явные from/to: history без from по умолчанию ограничен последним месяцем. Границы history — Unix секунды. Контракт — [OpenAPI](https://open.faceit.com/data/v4/docs/swagger.json).

Искать историю только запрошенного player_id, начиная с нового окна в 90 дней. Читать страницы и сортировать по finished_at с устойчивым вторым ключом match_id; порядок страниц проверить в API контракте. Дедуплицировать границы. При насыщении offset делить временное окно; если игр недостаточно, расширять поиск назад. 90 дней не являются скрытым пределом.

Для `/last` нужен один завершённый матч, для `/stats` — 30. При исчерпании бюджета сохранять checkpoint и обозначать incomplete selection, а не выдавать её за окончательные последние матчи. Никаких объединений историй участников чата и расчётов совместной игры в MVP нет.

## Визуальный шаблон

Подтверждён **FACEIT Dark**, выбранный пользователем в переписке: графитовый фон, оранжевые акценты, округлые панели, крупные значения. Обе команды возвращают только PNG (`/stats`: 864×1360, `/last`: 1200×1360) и inline-кнопки без подписей, текстовых отчётов или промежуточных загрузочных сообщений. `renderReportCard` выбирает шаблон статистики, матча или графического уведомления. Уведомления об ошибках и продолжении — PNG 864×640 с кнопками.

Статистика игрока: процент побед, W/L, текущие ELO/уровень, шесть метрик с краткими подписями KD/K/M/K/R/ADR/HS/K, форма, до семи карт по убыванию винрейта и период. Матч: результат и ориентированный на игрока счёт, K/D/A, показатели, до пяти карт и широкие составы с колонкой ADR, сортировкой каждой команды по ADR по убыванию и выделением игрока по ID. Счёт серии отличается от счёта раундов. Пропуски не превращаются в нули, приближённый ADR маркируется. Сортировки стабильные и не изменяют исходные массивы; отсутствующие/нечисловые ADR и винрейты идут последними. Служебные подписи покрытия, названия шаблона/API и пояснения о подсветке удалены. Переполнение области явно помечается, дополнительного текстового отчёта нет.

Фото резервируется до рендера/POST. Ошибка рендера может получить одну графическую замену под тем же идентификатором. При определённом или неизвестном отказе отправки текст не публикуется, повторный POST автоматически не производится. TeamSpeak секреты на изображениях отсутствуют.

## Архитектура и данные

Выбран JavaScript + Telegram Serverless. Облачный runtime: V8, SDK Bot API, SQLite и outbound HTTP. Ему не нужны VPS, Docker, Python, polling daemon, внешние LLM и внешний рендеринг. Временный локальный runner на Node.js 24 использует long polling и отдельную SQLite, пока доступ Serverless в листе ожидания. Код: `/Users/busygind02/IdeaProject/faceit-telegram-bot`.

Компоненты:

- `createFaceitService` — fixed HTTPS origin, обязательный ник, история и нормализация, отчёты с покрытием.
- `Store` — SQL с bound parameters, chat settings, delivery tombstones, report checkpoints, optimistic versions и leases.
- `createSealer` — AES-256-GCM-SIV из bundled noble-ciphers, AAD chat_id и отдельный от SQLite ключ.
- `renderReportCard` и text renderers — один источник PlayerReport, два шаблона FACEIT Dark PNG на Uint8Array без runtime npm/Node/Canvas.
- `createBot` и message/callback_query handlers — allowlist, членство, команды, кнопки, исходные группа/тема и точный native poll.

Таблицы: `chat_settings`, `deliveries`, `report_jobs`, `player_links` (в local/Sites также `report_cache`). Public FACEIT checkpoint не является реестром игроков. Нет сырых Telegram updates, переписки, списков участников и голосов. Foreign keys/transactions платформой не гарантированы; атомарные изменения TS и перенос chat_id выполняются одним SQL statement с compare-and-swap.

SDK не документирует secret env/Vault. Локальный генератор создаёт защищённые `.secrets/runtime.json` и ignored серверный `private-settings.js`: последний деплоится в библиотеку, но не на публичный сайт. Пользователи с доступом к облачным исходникам могут прочитать ключи; это не Vault и не защита от компрометации приложения. Ключ шифрования отдельно резервируется; возможности backup/restore самой облачной SQLite надо подтвердить у платформы.

## Доступ и устойчивость

- Рабочие команды — только в разрешённых группах с проверкой membership по Telegram user_id; для надёжного getChatMember бот должен быть администратором.
- Группа/тема доставки сохраняются из текущего update; кнопку продолжения нельзя перенести в другой чат или тему.
- Не логировать Authorization, secrets, тело /setts или сырые updates. Telegram текст отправляется без parse_mode; внешние строки ограничиваются и очищаются от control characters.
- Один активный тяжёлый расчёт на группу, последовательно до 8 GET за invocation. Это лимиты приложения, не квоты FACEIT.
- Нет документированного background scheduler. Длинный запрос сохраняет checkpoint и предлагает «Продолжить»; после нового invocation продолжает тот же снимок. Готовый отчёт старше пяти минут маркируется stale.
- 429 учитывает Retry-After, иначе backoff+jitter; GET продолжаются после ожидания. 401/403 объясняются владельцу без бесконечного retry. Неизвестный POST outcome автоматически не повторяется.
- Технические reports живут 7 дней, delivery tombstones 30 дней, уборка при запросах. TS не удаляется по TTL. Ник по умолчанию берётся только из явной личной настройки `player_links`, не из кеша и не из истории команд.

## Размещение и приёмка

[Telegram Serverless](https://core.telegram.org/bots/serverless) выбран пользователем. Доступ конкретному аккаунту BotFather, стоимость, квоты исполнения, фактический HTTP FACEIT, PNG InputFile и база требуют облачной приёмки. До её прохождения не утверждать, что бот развёрнут и работает 24/7.

Codex используется для разработки, а не как обещанный хостинг. Отдельная VM Стефании не подключалась и не требуется выбранному варианту. Корпоративные ресурсы не используются.

Нужны:

1. В BotFather включить Serverless и получить отдельный CLI Access token через интерактивный `tgcloud login`; Bot API token runtime SDK не требует.
2. FACEIT Server side API Key в локальном mode-0600 файле, один публичный тестовый ник и известный matchroom. Значения ключей в переписку не передавать.
3. Тестовые группы A/B/C с bot admin/send photo/send polls. Allowlist и безопасный bootstrap ID описаны в README проекта.
4. Разные TeamSpeak реквизиты задать непосредственно в группах, не в чате разработки.
5. Реальным опросом с двумя людьми проверить видимость авторов, множественный выбор, переголосование и все отключённые настройки.
6. Проверить limits Serverless и способы backup/restore базы; отдельно сохранить защищённую копию encryption key.

Личные FACEIT-привязки добавлены отдельно; общий реестр игроков и совместная статистика по-прежнему не входят в реализацию. Подробный локальный результат и оставшаяся приёмка — в `docs/verification.md` и `docs/acceptance.md` проекта.
